# 验证与覆盖记录

记录被审 base/head、工作区差异、工具版本和实际命令。先核实项目有该入口及其副作用，再运行；命令不存在写“尚未建立”，不要造测试命令。可运行已有软件检查，不能为了审查新增仓库脚本或自动启动硬件。

每条验收按下表记录：

| 验收/来源 | 独立 oracle/不变量 | 输入/工况 | 命令或数据链接 | SHA/配置/环境 | 结果与限制 |
|---|---|---|---|---|---|
| 本轮真实验收 | 方程、手算边界或独立参考 | 实际使用值 | 实际运行证据 | 实际版本 | PASS / FAIL / NOT RUN / NOT APPLICABLE |

NOT RUN 要解释原因及补证据方式；NOT APPLICABLE 要说明范围无关。测试 expected 不可由待测 helper 生成；同源模型互相一致不足以单独证明正确。关键修复检查旧错行为会否被回归用例发现，不伪造旧版执行记录。

覆盖 ledger 按实际路径标 `Reviewed / Not present / Not accessible / Out of scope`：

- 固件启动、状态机和故障/恢复；控制核与状态生命周期；采样、传感器、PWM 与中断；命令/日志。
- 仿真对象与传感器；控制器；多速率/延迟/求解器；接触；跨 C/MATLAB 接口。
- 实验配置、初始化/随机种子；原始数据/指标/图；构建/测试/依赖；需求/论文对应。

COMPLETE 表示当前声明范围的关键路径和必要证据已覆盖；关键项不可读/不可运行则 PARTIAL。当前验收要求但未实现的能力不能用 Not present 豁免。纯文档任务可在文档范围 COMPLETE，不能扩展成实现已验证。

尚未完成自己的覆盖工作时应继续审查，不以PARTIAL为理由等待Design再次派单。
真正不可读/不可运行且必要的证据写明障碍、责任人和恢复方法；不能用继续推进要求掩盖INCONCLUSIVE。
固定评审commit与工作树，仅冻结该树；运行前后核对该树状态，不能因其他独立worktree推进而误判输入被改。
新head按修复diff、风险和相关调用路径增量复审。可复用未变输入的构建/验证证据，但必须列原SHA/证据位置、
输入哈希与配置/工具/环境一致性及适用范围；输入或依赖改变的受影响检查重新运行。复用不等于继承旧整体PASS。

发布前核对远端 head/base，记录核对时间与 Version status：一致为 CURRENT，已变化为 STALE，无法核对为 UNVERIFIED。新 head 需复审，base 变更需重新核对差异和相关验证；后两种状态均不得给当前版本 APPROVE。日志来自带未提交修改的工作区时明确披露，不能冒充干净 head；共享目录意外改动导致验证输入不确定时，受影响证据作废并重新验证。必要证据无法取得且尚不能判定失败时，总体结论用 INCONCLUSIVE，说明恢复方法。合并建议只针对对应版本和证据等级，不自动授权合并。
