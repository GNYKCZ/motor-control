# M3B3：精简故障诊断帧与导出热点

Refs #1、#7；基线main `c95ae0e3ef69d42a4c957247b765e2d585cbda55`（PR #16合并）。
用户明确要求同时减少发送数据、转换/打包、无用计算与性能开销；Design确认本批只服务
反馈积压验收，不扩展控制功能。本批交付软件优化及诊断，真实fo消除/耗时仍NOT RUN。

## 实测依据与边界

2026-10-28用户复制三条M3B2：`s=2,f=8,fo=1`，raw有效、候选512收齐；
`fb_poll_us=110,fb_step_us=104,mb_max_us=16,mb_overrun_us=1000`，
`tp1=1999,tp3=1127,tp11=1303,tp12=1299`us。多个日志步骤超过约1ms输入间隔，
足以否定旧分段粒度的时间预算。最大观测含抢占，不能确定首个故障恰由哪个段触发。
这不是完整串口流，确切烧录二进制未独立读回核验；详本机忽略目录
`build/serial_example_inspection/m3b2_user_timing_failure_20261028_111348.*`。
已请用户结束该轮；本批不自行烧录、复位、上电、手转或改变物理接线。

## M3B2逐字段取舍

原M3B2共71字段，新M3B3固定16字段。删字段不等于所有字段都能从低频日志重建。

| M3B2字段 | 本批处理及理由 |
|---|---|
| s、f | 保留：运行状态/锁存故障，故障后仍导出 |
| n、t | 保留：最新ADC完成序号/设备us，检查运行推进、重启和日志间隔 |
| u、v、a、ok | 保留：原始两ADC/编码器count及整帧有效，失败原始值不抹去 |
| fp、fd、fw | 保留：反馈有效/直接及窗口估算器就绪；本轮不输出速度数值、不验收精度 |
| fo | 保留：单槽溢出计数，锁存故障不擦证据 |
| fb_poll_us | 改名fb_us：保留整次有输入反馈poll最大观测 |
| fb_step_us | 删除输出和单独测量：本轮已有104us基线，保留聚合poll即可，少两次设备取时 |
| mb_wait_us、mb_max_us、mb_overrun_us | 合并mb_us：消费等待与溢出未消费年龄的同一最大观测 |
| tp0_us..tp13_us | 改为log_us/log_id：单步最大观测及具体步骤ID，不再维护/复制14项数组 |
| e、es、ec、fe、ft、fr、fm、fdt、fn、ff | 退出本轮周期帧：内部仍检查原始序号/时间、估算器首帧/预热；故障由f及有效位呈现 |
| mg、bad | 不周期导出：ok/f用于本轮帧门控；编码器状态/CRC检查、runtime坏帧统计保持 |
| skip | 不导出且不再维护telemetry跳过计数：忙时有界放弃，n/t和主机时间可观察接收间隔，不能据此唯一归因丢帧 |
| cn、cb、ca、cd、cv | 不周期导出：零偏候选不是本轮故障验收的核心；内部512帧统计/冻结与cv未验证语义保持 |
| ou_mc、ov_mc、umin、umax、vmin、vmax | 校零阶段专用；停止导出均值计算/打包；内部统计保留。低频u/v不能重建整批范围或均值 |
| mv、iu_mA、iv_mA、ma_mrad | 删除导出名义换算：本轮不校准电流；机械单圈角可从a在主机换算。电流需另有偏置/比例依据，不能直接称实测A |
| fc、fa_mrad、vd_mrad_s、vw_mrad_s、wd_count、wdt_us | 不做double/64位展示或打包；核心反馈仍计算并门控。10Hz的a/t可能回绕混叠，不能重建真实连续轨迹/速度，后续精度阶段需专用证据 |
| scale_nA、fs、dir、dir_ok、pwm、power | 固定构建/阶段信息移到契约/元数据，不逐帧重复。方向未标定、PWM永久禁止、功率桥高阻未验证仍成立 |

不删除ADC/编码器采样、CRC/有效性、零偏统计、feedback_step或任何故障门控；
不改stride=10、300us原始断流、3000us反馈间隔/发布年龄、单槽不覆盖或锁存故障。
不引入UART接收、命令、使能、对齐、CRC新协议、DMA发送重构或硬件控制。

## 固定M3B3帧

```text
M3B3,s=1,f=0,n=123,t=12300,u=2027,v=2028,a=16372,ok=1,fp=1,fd=1,fw=1,fo=0,fb_us=110,mb_us=16,log_us=20,log_id=4\r\n
```

示例为合成说明，末尾是实际CRLF两字节，不是反斜杠文本。

| 字段 | 单位/范围和含义 |
|---|---|
| s / f | 0BOOT/1DISABLED/2FAULT；故障位1初始化、2采样、4设备、8反馈，可组合，uint32保留未知位证据 |
| n / t | 最近ADC完成序号/完成时刻us，uint32模回绕；不是电脑时间或每秒样本数 |
| u / v / a | 原始count，uint16；ok=1时u/v<=4095、a<=16383，ok=0时仍保留失败原始值 |
| ok / fp / fd / fw | 0或1；整帧有效、位置反馈有效、直接估算就绪、窗口估算就绪。无速度数值就不能声称已验收速度精度 |
| fo | uint32单槽溢出次数，非0时对应锁存反馈故障 |
| fb_us | uint32反馈poll最大观测墙钟us，含取时/抢占，不是严格WCET |
| mb_us | uint32邮箱等待/未消费年龄最大观测us；起点均为该输入所属ADC完成时刻，含发布前IRQ处理 |
| log_us / log_id | 日志单次poll最大观测us及其步骤ID；同值保留最先记录的ID |

mb_us在消费时使用当前设备时间，溢出时使用检测事件的ADC完成时刻，并取同一个最大值。
因此既能保留正常等待，也不会在故障清空邮箱时丢掉未消费年龄；不是等待平均值。
fb_us删除了旧单独step计时的两次取时开销，不能据数值变小就声称反馈算法本身加速。
计时1us分辨率、uint32有界模差；0可能未观测或低于分辨率，不代表零成本。
所有最大值都是有限观测。fb/mb故障后保留；log在继续导出时还可能增长，不能唯一指认首个故障步骤。
fb/mb在runtime初始化时清零，log从程序启动累计到整机重新启动；本批没有在线清除命令。

log_id：0=准备；1..16依次对应`s,f,n,t,u,v,a,ok,fp,fd,fw,fo,fb_us,mb_us,log_us,log_id`。
每行的status与log最大值/ID在准备时冻结；本行刚发生的新日志耗时由后续行呈现。
组装中途出现新帧/故障，不混入当前历史行；下一行再呈现新状态。
缺少pwm/power标签不表示功率已验证，只因当前阶段固定输出禁用并已在元数据声明。

## 有界处理与资源预算

`motor_runtime_read_log`直接在短临界区复制约40B实际所需数据，保留完整read_status供
主机/调试，不先拷完整状态再裁剪。telemetry不再调用sensor_input_convert、不计算零偏均值、
不读取零偏范围、不进行rad/A或64位展示转换，也不复制14个耗时元素。
核心sensor_offset_add/feedback_step继续实际执行，控制核无HAL依赖。

每100ms尝试开始一行。第0次只取小快照/前缀，后续每次只转换一个uint32，
十进制除10/取余最多10轮，固定字段名最长6B；无printf格式解释、动态分配或阻塞等待。
不通过大段格式化后再切片来假装让出。完整行才提交UART，TC之前不重写借用缓冲；
忙、快照失败、容量不足或提交失败则放弃本行，到后续周期再试，不维护未输出skip计数。

按协议范围最长169B含CRLF，115200/8N1传输约14.67ms；若全部16数值均保守按10位uint32，
总长237B加NUL仍不超过256B缓冲。理论最大周期数据量1690B/s，不等于保证实际10Hz或严格截止时间。
与M3B2保守1192B上界相比，发送长度及每字节UART IRQ负担显著减少；真实CPU时间仍待板测。
编译目标资源与警告绑定最终head记录在PR；不能把静态循环界限当实测WCET。
