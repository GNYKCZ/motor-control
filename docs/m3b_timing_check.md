# M3b：前台分步导出与积压诊断

Refs #1、#7；基线main `9bf9797459f0071e193c68c4ffa3cd5d20e708e1`（PR #15已合并）。
本批针对用户自烧录M3B1后报告的`f=8,fo=1`，修复一次整行格式化独占前台的调度风险，
增加下次板测所需的有限观测计时。**未证明它是积压唯一根因，也未证明板端积压已消除。**
不扩大邮箱、不改抽帧步长/过期门限、不取消故障、不自动清故障，不新增控制或硬件操作。

## 调度修改

主循环仍按deadline→feedback→telemetry调用。原来一个poll完成名义换算和整行snprintf，
现在第0次准备冻结快照，第1..13次每次只完成一个固定小段，最多7个整数转换后返回。
下一次前台迭代先服务反馈，不在telemetry内递归调用runtime或关闭中断格式化。
准备步骤仍包含名义换算；它和feedback_step也可能耗时，必须由新增计时观察，不能排除。

status、名义换算、跳过数和各分步最大耗时都在准备时冻结。组装期间即使新帧或故障到达，
整行仍描述旧快照，各字段不会拼接成不同采样时刻；下一行再描述新状态。
日志是带时标的历史观察，不是接收时刻的即时状态；UART传输本来就有延迟。
只在完整行组装成功后提交UART；TC前借用缓冲不重写。忙/格式失败/提交失败仍计skip，
半行不提交，任何步骤都不等待UART。每100ms尝试开始一行，不保证固定10Hz输出。

## M3B2计时协议

前缀改为M3B2，保留M3B1全部字段、单位和有效性语义。
`sensor_capture.py`同时支持M1/M2C1/M3B1/M3B2，旧故障证据仍可解析。

| 新字段 | 定义，单位us |
|---|---|
| fb_poll_us | 有输入的反馈poll从持锁取走输入到发布检查完成的最大观测墙钟时间 |
| fb_step_us | feedback_step周围两次设备取时的最大观测差值 |
| mb_wait_us / mb_max_us | 上次取走输入时距该ADC完成时刻的等待时间/其最大观测值；含发布前IRQ处理 |
| mb_overrun_us | 单槽满时，本次与待消费输入所属ADC完成时刻之差；首次故障后保留 |
| tp0_us | 准备冻结快照/名义量的最大观测耗时 |
| tp1_us / tp2_us | 原始帧时标字段 / 原始值与坏帧、skip字段的最大观测耗时 |
| tp3_us / tp4_us / tp5_us | 候选统计 / 原始范围 / 名义测量字段的最大观测耗时 |
| tp6_us / tp7_us / tp8_us / tp9_us | 反馈标志与输入 / 连续角 / 两速度窗口 / 配置与积压字段的最大观测耗时 |
| tp10_us / tp11_us / tp12_us / tp13_us | runtime诊断 / 分步计时0..6 / 分步计时7..13 / 结束标签及UART提交的最大观测耗时 |

计时用既有TIM4 1MHz设备时钟，uint32模差；假定一次被测过程小于完整时钟周期。
结果含取时开销和IRQ抢占，分辨率1us；0可能是尚未观测或低于分辨率，不能理解为零成本。
只记录有限运行中的最大观测值，**不是严格WCET、栈水位、速度精度或截止时间证明**。
runtime诊断在故障后保留，只有重新初始化清零；IRQ仅额外记录整数overrun间隔，不跑double。
各tp值在准备时冻结，因此本行自己的新耗时要到之后的行才可见，至少观察多行。
整行最大整数长度1192B加NUL不超过1536B缓冲，capture上限2048B不变。
最坏长度按115200/8N1可能跨越100ms，忙时允许计skip，不宣称串口始终有发送余量。
