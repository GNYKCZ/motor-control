# M3b：板端反馈路径的软件集成

Refs #1、#7；基线 main `dfd3b191d87e440c39a1470f462f28f42c0b54e7`。
Design 在用户接受下一批后确认：将 M3a 的连续机械角、直接速度、窗口速度接入唯一固件。
本批是软件集成，不是速度闭环，不新增控制指令、PWM使能、自动对齐或硬件操作。

## 调度与所有权

实际配置仍为72MHz、TIM1中心对齐、原始帧约99.94us（约7196 CPU周期/拍），未改变生成初始化。
这是原始采样的计划间隔，不等于新增算法的可用CPU预算：ADC、SPI/DMA和异常处理仍占时间。
无FPU的Cortex-M3需要软件double库，不能把原feedback_step直接加入该中断。

`motor_runtime_handle_sample`对每个完整原始包检查有效性、ADC序号和encoder序号各自严格+1。
两种序号不要求相等；首个有效帧建立基线，原M1首次无效帧等待宽限保留。
首个有效帧及其后每10个原始帧生成一个真实encoder输入，单槽邮箱交接。
邮箱未消费又到下个抽帧时，增加`fo`并锁存FEEDBACK故障，不覆盖未消费输入。
原始跳号即使发生在非抽帧点也锁故障；raw证据仍按原M1值域/时间规则保留。

`main`前台依次检查采样失联、消费反馈邮箱、低频导出。
`motor_runtime_poll_feedback`短临界区复制输入并取走邮箱，离开临界区再调用canonical反馈模块。
IRQ从不读写feedback_state，不做浮点或历史复制；算法状态仅由前台拥有。
发布时重新核对运行状态，故障中途发生时不能重新发布有效结果。
发布时持锁读取设备当前时间：距本次反馈输入完成超过3000us，或距最新ADC超过300us，
均先锁故障/失效，不静默发布过旧结果；即使采样停止，当前时钟仍会推进。
所有故障清空已发布反馈及待处理邮箱，保留故障/积压证据；无自动复位。
`motor_runtime_init`只能在采样启动前调用，重新建立原点，不能在线重入。

前台是忙轮询，**只承诺每10帧产生一次输入、前台尽快消费，不承诺严格1kHz调度**。
double除法、低频格式化仍可能造成积压；故障检测不是实时性能证明。
本批不将double接入高频中断；板端耗时、临界区最大时间、栈水位、最大处理延迟均NOT RUN。
后续实测须另行安排，覆盖窗口满拍、串口负载、故障路径和中断嵌套，再确定实际余量。
约1ms反馈间隔不是未来速度环固定周期。

RV-001：独立首审复现了旧发布检查误用“最后ADC时间”作为当前时间，停采样并延迟5ms后
仍可能先导出fp=1、到下一轮deadline才锁故障。修复为锁内取当前时钟并同时检查上述两个门限。
回归覆盖deadline通过后在取邮箱前/解锁计算时推进时钟、uint32回绕、300/301us边界，
以及解锁后正常新ADC发布；过期场景的真实runtime/telemetry必须在本轮返回FAULT/fp=0。
同一回归已使首审旧runtime失败、修复版通过；旧版诊断仅替换assert失败出口为stderr/exit，
保留全部断言表达式，避免Windows交互弹框，证据保存在build/m3b_rv001_old_regression.json。

## 反馈数学与兼容

直接编译[同一feedback实现](../control_core/feedback.c)，不在板层复制算法。
新增`feedback_init_spaced`，初始化时固定真实序号步长10；默认`feedback_init`仍严格步长1。
reset保留步长，只有重新初始化才能改变；从不将真实encoder序号重编号。
原始流完整性由runtime逐帧验证，抽帧点之间的时间与角差仍受M3a实际dt/半圈歧义门控。
32点固定容量保留；为适配1KiB主栈，事务计算只暂存标量，全部检查通过后写单个历史槽。
失败时状态全部字节不变，输出全零；既有跨圈/溢出/长时间/两实例oracle继续回归。

本板计划窗口9点，maximum_gap=3000us，maximum_read=40us；速度先验100rad/s，
方向+1仅沿用raw计数正向，**未经实物方向标定**；速度先验不是测量或保护能力。
若真实运动不满足先验，输出不能作为可信反馈。首帧相对原点0，两种速度无效；
第二个抽帧起直接速度有效，第9个抽帧起窗口速度有效，窗口约跨8ms但使用实际dt。
窗口值表示首尾平均速度，相对直接法有响应延迟；本批不声称实机噪声或延迟改善。

## M3B1日志

保留全部M2C1字段、单位及`pwm=blocked,power=unverified`，新增字段如下。
同一行raw部分是最新包，反馈部分可来自更早的抽帧，必须用各自序号/时标对应。
输出每100ms尝试一次，不是逐帧轨迹；采集工具仍只读，不发送指令。

| 字段 | 含义 |
|---|---|
| fp/fd/fw/ff | 反馈位置/直接速度/窗口速度有效，以及首帧标志 |
| fe/ft/fr/fm | 反馈输入的真实encoder序号、读取完成us、raw count、读取中点us |
| fdt/fn | 相邻抽帧实际中点间隔us、已填窗口点数1..9 |
| fc/fa_mrad | 相对首帧的精确有向int64 count、机械连续角mrad |
| vd_mrad_s/vw_mrad_s | 直接/窗口机械速度mrad/s，向0截断 |
| wd_count/wdt_us | 窗口首尾有向int64计数差及uint64真实间隔us |
| fo/fs | 邮箱满的交接失败次数、固定真实序号步长10 |
| dir/dir_ok | raw正向+1、物理方向已标定标志恒0 |

首帧的fdt/fc/fa/两速度/窗口差分均0；未满窗的窗口数值0。
fp=0时反馈数值及其有效标志全部0，fo/fs/dir/dir_ok仍保留配置与失败记录。
发生故障仍导出最新raw，不把无效速度0解释成静止。
角度/速度文本量化误差小于1mrad或1mrad/s（double计算误差另按M3a预算），
fc保持整数精度；连续角在绝对计数超过2^53后不保证逐计数精度。
`sensor_capture.py`兼容M1/M2C1/M3B1，64位字段独立检查，不按32位截断。
行缓冲1024B，最坏数字长度由合成边界验证；UART忙时跳过并计数，借用期间不改行缓冲。

故障位新增8=FEEDBACK；1/2/4保留。新增原始连续性故障会使旧M2c允许raw有效但
只中止候选的跳号路径进入FAULT，这是本批有意增加的反馈门控，不改raw有效性含义。
