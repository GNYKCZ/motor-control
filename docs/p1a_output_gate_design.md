# P1a 受控输出入口与门控设计

Refs [Issue #1](https://github.com/GNYKCZ/motor-control/issues/1)。设计基于 main
`472d108ad8fa5da2541fadf0904f790e2e1d227f`，与 M3B3 源提交
`30a1ba64396edf89db65dfa27cea5dac573bcfeb` 的树相同。
本批仅交付来源核对、接口和验收设计，没有修改固件、生成初始化或下载配置，没有执行硬件操作。

P0 已按用户接受的基础功能口径完成：Keil 第二次下载 Verify OK 与电脑映像对应，
有限 VOFA 摘录显示有效采样，不同静止位置的 raw a 可区分。用户说明换位时没有断电；
没有连续原始流或长期稳定性结论。P0 完成不代表 P1 输出、电流或停机已经验收。

## 最小范围和交付顺序

P1a 的目标是让显式请求经过状态、输入有效性、幅值和时限校验后才能产生一次受控输出，
正常结束、停止或故障都撤销该次输出资格，复位不自动重启。
先实现可到达的命令入口，再接输出；不先增加无人调用的 PWM API 或默认激励。

1. 下一批 P1a-1 可先实现 UART 接收、STATUS/STOP、限长解析与回执，仍保持 M3B3 的 PWM 禁止。
   先用不含输出动作的交互核实 RX 物理链路；软件测试不能代替这次现场收发核实。
2. P1a-2 才接一次性 PWM 门控。前提是明确实际驱动、实验输入限值、时长、触发与停止条件，
   并审查 CubeMX 差异及门控竞态。首次板端输出须由用户另行安排，PR 合并不是运行授权。
3. P1b 再做无相电流条件、零偏候选、通道与电流符号；P1c 再核对相序、机械到电角方向、
   极对数与电零位，接入正式 d/q 电流闭环。已有主机算法不算这些板端步骤通过。

不迁入例程自动对齐、默认电流、速度/位置环、阻塞串口或全套 DSP；不新增硬件。

## 参考例程与本项目逐项对应

来源为黄铮 best_pureer 的 [stm32_foc_2](https://gitee.com/best_pureer/stm32_foc_2)，
本地冻结提交 `672e32f1005d9019140d1a9c754fb8ca2e8eedde`。
本次核对其 .ioc、tim.c、adc.c、main.c、gpio.c、usart.c、conf.h、foc.c、原理图和开箱说明；
本地参考工程仅 MDK 工程配置有未提交修改，未参与下列源码判断。
不复制作者 USER CODE 或整份资料，既有[来源与许可](../firmware/stm32f103/SOURCES.md)保持。

| 参考文件、函数或网络 | 本项目现状和 P1a 处理 |
|---|---|
| stm32_foc_test.ioc、tim.c: MX_TIM1_Init | PA8/9/10 对应 TIM1 CH1/2/3，中心对齐 PWM1；本项目 .ioc 当前仅配置 TIM1 计数/TRGO、三引脚 GPIO 低。需要 PWM 时从 .ioc 生成，不能手改生成区补配置 |
| main.c: set_pwm_duty | 参考把浮点占空比直接写 CCR1/2/3；未来由 board 独占整数 tick 提交，runtime 先校验整个请求；不允许 core/main/串口各自写 CCR |
| main.c: 三次 HAL_TIM_PWM_Start | 逐通道启动会带来不同启用时刻，不能直接照抄；未来预装三路 CCR、保持 MOE 关闭，完整校验后统一提交使能 |
| main.c: (0.5,0,0) + HAL_Delay(400) | 这是上电强拖对齐；P1a 不迁入，不以复位/上电触发输出 |
| main.c: motor_mode_torque(0,0.3) | 例程默认 0.3 A 不是本次允许电流；不迁入，不直接使用例程粗调 PID |
| adc.c: HAL_ADCEx_InjectedConvCpltCallback | 例程在 ADC IRQ 内换算电流、Park、PI、foc_forward；当前 board 只发布双 JEOC 完整原始包，P1a 不引入整条 FOC 调用链 |
| foc.c: foc_forward → svpwm → set_pwm_duty | 本项目 control_core/foc_math.c 已有独立数学契约；P1a 不让它直接依赖 HAL，也不把非零电压矢量默认为允许输出 |
| adc.c: ADC1 PA0 / ADC2 PA1 双注入 | 本项目保留同一模拟通道、7.5 周期采样和 TIM1 update TRGO；CRC/时间/序号门控不删 |
| tim.c: TIM2 ITR0 reset、78 us SSI | 当前由生成 TIM2 比较 50 us + board DMA 事务替代，保留完整帧发布、CRC 和年龄检查；不退回例程直接读 DMA 缓冲 |
| gpio.c: PB12 TIM1_Break | 参考实际是 GPIO 上升沿 EXTI，TIM1 BreakState 为 DISABLE；未发现自编 EXTI 回调执行门控，名称不代表有效低硬件 BKIN 已启用 |
| 当前 board_io.c: ADC1_2_IRQHandler | 每次完整 ADC 事件读 PB12，低则锁存设备故障；目前无硬件 BKIN，不能称为异步硬件保护 |
| usart.c: TX_RX 与阻塞 fputc | 当前 USART2 是 TX-only，board TXE/TC 非阻塞借用缓冲。未来从 .ioc 打开 RX，统一由 board IRQ 拥有 UART，不混入 HAL 阻塞接收/发送 |

## 原理图事实和实际装配边界

参考原理图 V2.0 的 U4 标注为 MS8313/DRV8313PWPR，并未唯一指定实际装配型号。
PDF SHA256 为 `4c6a06ba8bf2248cd2d7322b7ecbbe3bf167cc86d76116d081d8808260add1bf`；
开箱说明 SHA256 为 `2274bf2e4a0b17dd4595f692130f3837da942eb59d5e59083e2e0e42841346a0`。
开箱说明明确板卡可能改版，应以实际丝印为准；其自动转动后位置保持描述不能替代当前代码事实。

| 原理图连接 | 可采用的设计事实 | 不能据此宣称 |
|---|---|---|
| PA8→IN1、PA9→IN2、PA10→IN3；OUT1/2/3→U/V/W | 三路集成半桥输入，不需要新增六路互补栅极信号 | 尚未测实际相序、电流符号或输出波形 |
| EN1/2/3 接 8313_3.3V | 当前 MCU 没有逐相 EN 控制 | MOE=0 就能高阻关闭功率桥 |
| nSLEEP、nRESET 固定接驱动的 V3P3OUT 网 | 无 MCU 休眠/复位驱动的接口 | MCU Reset 等于驱动断能/清除所有驱动故障 |
| nFAULT→PB12，4.7k 上拉到驱动侧 3.3V，另有 LED | 故障有效低；首次输出前须确认实际信号与供电状态 | 固件只读高电平即可证明所有内部保护有效 |
| 两路 INA199A1、20mΩ 与1.65V名义偏置 | 只构成名义电流换算来源 | P0 已证明零相电流或绝对电流精度 |

按 [DRV8313 数据手册](https://www.ti.com/lit/ds/symlink/drv8313.pdf)，EN 高、IN 低为低侧导通，
EN 低才使该半桥高阻。三路输入低可称低侧制动/停止调制，不能称切断供电。
DRV 内部处理半桥换向，不照搬分立六管驱动的互补死区设置；实际若为 MS8313，须依据其准确型号资料
核实接口与内部换向约束，不能把 TI 的死区或保护参数当作 MS 实测。

首次输出前只核对不确定的 U4 丝印/板卡差异，无需重新拍整板或拆相线。
12V 与 USB/DAP 逻辑供电继续分别记录；普通适配器的限流/实际电流未知如实保留，
不从“原例程能转”推断任意 PWM 激励都可接受。实际停机可用现有方式切断两路供电。

## 可到达的命令入口

首选 USART2：原理图 PA2 TX、PA3 RX 分别引到 H8 的 TX/RX，参考 usart.c 为 TX_RX。
当前本项目 PA3 已生成输入引脚，但 USART2.Init.Mode=UART_MODE_TX，RX 没有软件接收路径。
用户通过现有 DAP/COM9/VOFA 已收到日志，只证明 PA2→电脑可用；不能证明 DAP TX→PA3 导线已接通。

下一批先在不启用 PWM 的固件中实现 STATUS/STOP 回执，使用同一 COM9，避免同时被 VOFA 和主机工具占用。
现场仅需根据已有 DAP 接口说明或现有接线核对串口 TX 是否通到板 RX，不能把 SWDIO 当 UART TX。
逻辑信号须兼容板 RX，不接 RS232 电平或把供电脚当信号；不要求增加串口模块。
即使双向线已接，当前 M3B3 也不会响应命令，不能据此判硬件 RX 损坏。

拟定的最小逻辑命令为 STATUS、STOP、ARM、PULSE；P1a-1 只实现前两者。
ARM/PULSE 未实施前必须明确拒绝，不能回显成功却没有对应状态动作。
未来 ARM 只建立一次性软件资格，不输出；PULSE 消耗该资格、引用一个已批准的固定实验 profile，
不让任意串口浮点数直接成为占空比/电流/持续时间。结束或 STOP 均回到 DISABLED，再次输出需要新 ARM。

协议实现批次须固定版本、最大帧长、命令序号/重复拒绝、CRC、超时丢弃和回执语义，并有负向测试；
CRC 解决传输错误，不是电机电流保护或用户运行授权。IRQ 只收有界原字节，前台每轮解析有界工作量；
接收溢出/错误不能覆盖旧命令或延长输出，ACTIVE 时锁存通信故障并停止。STOP 不因等待发送回执而推迟门控。
上电/复位清除资格和待处理请求，不能重放重启前缓存的输出命令；主机重连不自动 ARM/PULSE。

若现有接线确实没有 RX，替代是板载 PA12 自定义按键：原理图按钮接地，需 .ioc 配置输入上拉、
有界去抖和一次性按下/释放序列。复位时已按住必须拒绝，避免长按重启即输出；
不能拿 Reset 键代替输出按钮。按键只能触发预先批准的 profile，参数与回执受限、误触风险更高，
须另行确定交互再实现。调试器改内存/强改寄存器不作为正常调用者，调试暂停可能冻结高电平或超时机制。

## 状态和板级提交契约

以下为待实现接口设计，不表示本批已有 API：`output_request` 表示完整值对象请求，
`output_start`、`output_stop` 为 runtime 内部入口；`board_apply_pwm`、`board_disable_output` 为板级动作。
简明英文命名保持一致，单位、临界区、提交顺序和停止语义以中文注释说明。
control_core 保持硬件无关；不为了门控状态在 core 预建无调用者框架。

| 状态 | 可接受动作 | 输出与转移 |
|---|---|---|
| BOOT | 初始化/故障 | 始终禁止调制；成功到 DISABLED，失败到 FAULT |
| DISABLED | STATUS、STOP、满足条件的 ARM | 无调制；ARM 资格在 RAM，任何重启清除 |
| ACTIVE | STATUS、STOP、故障/期限到达 | 仅已接受的一次 profile；新 ARM/PULSE 拒绝，不能续期 |
| FAULT | STATUS、STOP | 故障锁存、撤销资格/请求；无自动恢复或自动重启输出 |

开始前在同一状态事务核对：初始化完成、样本/反馈新鲜有效、无锁存故障、nFAULT 为高、
profile 已批准、三路 tick 与最大相间差均在该 profile 范围、时长合法且未溢出。
校验失败不写部分 CCR、不改变输出状态。停止/故障可抢占开始；先前检查通过不能在随后故障后重新置 MOE。

board 提交先保持 MOE 关闭和已定义的输入低，再写三路预装 CCR；
由 CubeMX 生成的 PWM1、预装载、空闲低电平和输出配置须核对实际寄存器。
只在受控边界切换 AF/通道并统一开门，不能让第一相先于另两相出现半个未审脉冲。
运行中不能随意发 UG 刷新 CCR：TIM1 update 同时驱动 ADC/TRGO 和 TIM2，
必须证明同步操作不制造伪采样、改变 RCR 相位或破坏编码器时间关系。
停止先清 MOE/CCER，再切 GPIO 低；保留计数/TRGO 和故障数据。不得把三路等占空比直接当无相电流证明。

候选硬件故障门控是 PB12/TIM1_BKIN 有效低、BKE 开、AOE 关，外加 runtime 故障锁存；
必须由 .ioc 生成并核对 PB12 复用、空闲电平及故障保持语义，不能靠标签名。
BKIN 关闭 MOE 也不是驱动 EN 断开；不能据此宣称高阻或已有保护认证。

## 时序和输入限值

72MHz、中心对齐 ARR=1799 的完整 PWM 周期为 2×1799/72MHz，约20.011kHz；
参考 conf.h 的 motor_pwm_freq=40000 不是此配置的完整中心对齐波形频率。
RCR=3 的更新/ADC 触发约每7196个时钟，即99.944us；不是每个 PWM 边沿都采一次电流。
ADC 时钟12MHz，7.5+12.5周期约1.667us，未计 IRQ 延迟；
SSI 50us开始、24bit/1.125MHz约21.333us，保留现有时间预算与 CRC/序号校验。
改变占空比后，原 TRGO 相位不自动保证低侧采样电阻窗口有效；P1a 不用这些 ADC 值完成电流环验收。

参考 conf.h 的 Rs=5.5Ω、Ld=.0007185H、Lq=.000905H、12V/7极对仅是名义来源，
未核实为该实物参数。当前不能从这些值直接批准 0.3A、1%占空差或10ms激励。
profile 必须写明三路 tick/相间差、时长、适用供电/板卡、允许操作和停止条件及依据；
输入未定时默认无可输出 profile，不能补一个随意常数让验收可运行。

持续时间不能只靠主循环、UART STOP 或日志判断。可用空闲 TIM3 作独立期限 IRQ，
开始前布置期限，ACTIVE 期间禁止请求续期，期限路径只做有界门控，结束后等待显式新请求。
但这仍是 CPU/IRQ 参与的软件时限，不是 CPU 停机时仍可靠的独立硬件断能；
需测量 IRQ 延迟、最长临界区和门控耗时，不能将“配置10ms”写成严格10ms断能保证。
首次输出不进入调试暂停；时基回绕、异常返回、FAULT 与 STOP/开始同时到达都须覆盖。
现有 M3B3 fb_us/log_us 有限观测不能充当增加 RX/PWM 后的预算；新增路径须重新构建和计时。

## 最小文件和验收计划

本 PR 仅增加本文及 README 入口。后续实现按实际调用路径选文件，不一次展开全部 P1：

| 子批 | 预计文件职责 | 独立判断依据与软件验证 | 板端证据/目前状态 |
|---|---|---|---|
| P1a-1 RX/回执 | .ioc 和生成 usart；board UART IRQ/RX缓冲；有调用者的命令解析；runtime STATUS/STOP；小型主机发送工具及真实集成测试 | 有限长度/CRC/序号文本 oracle，半包/噪声/超长/溢出/重连/并发TX；STOP不等待回执，ARM/PULSE明确拒绝 | 无输出 STATUS/STOP 往返确认现有RX；NOT RUN |
| P1a-2 PWM门控 | .ioc生成 TIM1/引脚/BKIN及期限定时器；board统一提交/停止；runtime 状态与显式请求；必要紧凑状态字段 | 三相原子提交、故障优先、边界tick/时长/回绕、期限与STOP、复位无自动输出；含真实board寄存器路径的测试，不仅mock runtime | 已批准profile、实际U4与供电/停止条件；首次输出另安排，NOT RUN |
| 生成与目标闭包 | 原有 regenerate_m1.py、verify_m1.py、ARM/MDK入口按实际接口必要调整 | CubeMX6.12.0/FW_F1 1.8.6 再生成一致、来源哈希、真实编译依赖、资源/警告；用户Keil配置保留，必要时干净工作树严格校验 | 软件PASS不替代板端；本设计PR不改这些入口 |
| 端到端实时预算 | 主机命令→runtime→board与紧凑诊断 | RX洪泛/串口忙仍服务采样；原100us采样/stride10、300us/3000us门限与锁存回归，不放宽门限通过 | 命令行、MCU时间及故障记录；NOT RUN |

没有示波器时，MCU 可报告实际读取的配置寄存器、启停请求与设备时间、故障位、计数器推进，
并用原始数据支持软件观察范围。寄存器设为PWM不能证明 PA8/9/10 真有对应波形；
这些证据不能确认外部死区、脉冲完整性、实际桥输出、电流瞬态或复位电气过程。
没有仪器的项目如实标未测，不伪造“波形已通过”，也不把购买仪器设为当前文档交付前提。

首次输出前缺失的最少现场输入为：实际U4丝印/与V2.0差异、现有DAP的TX到PA3是否可用、
两路供电与立即切断方式、所选实验profile的限值与依据。先充分使用已有资料，不重复要求整板照片。
当前可以审查和实现 P1a-1 的无输出收发软件；不能据本设计直接执行非零输出。

原理与约束依据：[ST RM0008](https://www.st.com/resource/en/reference_manual/rm0008-stm32f103xx-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)
的 TIM1 PWM/预装载/Break 机制及上述 TI 数据手册；实际器件与板端行为仍须单独核实。
