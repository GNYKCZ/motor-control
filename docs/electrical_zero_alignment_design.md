# 电零位：单U50%/20kHz参考例程方案

Refs Issue #1 / PR25。用户已明确要求参考例程、提升到50%、采用第一份例程ARR而不保留1799。
本轮Design仅更新方案，不改固件/测试/Keil、不提交推送、不操作硬件。本文取代此前60/120tick及两点方案的后续设计；历史结果不变。

## 已决定的目标与直接源码

| 来源 | 实际配置/行为 |
|---|---|
| 本地stm32_foc/Core/Src/tim.c及conf | PSC0，Period=72MHz/40000=1800，中心对齐，RCR4 |
| 本地stm32_foc_2/Core/Src/tim.c及conf | PSC0，Period=SystemCoreClock/40000-1=1799，中心对齐，RCR3 |
| 两份Core/Src/main.c强定义set_pwm_duty | CCR=占空比*ARR，固定(0.5,0,0)保持400ms，读取当前机械角为rotor_zero，然后三相归零；0.5不是0.5V |
| 原例程初始化期间 | control_type_null为0且默认BSS为0，没有在该保持段通过电流/位置闭环纠偏；p7来自配置，未辨识p/d |

用户目标采用第一份载波：PSC0、ARR1800、中心对齐、CCR=(900,0,0)，固定U400ms。
频率主差来自原PSC9改0，1799本身不是缺陷；不是声称两份参考都用1800。
边沿计数0..ARR共ARR+1个时钟；中心计数0..ARR-1再ARR..1，共2*ARR个时钟。
所以f_PWM=f_TIM/((PSC+1)*2*ARR)=72MHz/3600=20kHz；1799则约20011.12Hz。PSC的分母始终是PSC+1。
依据STM32F103 RM0008高级定时器计数/重复计数器章节及原字节HAL生成路径：
[ST发布的RM0008副本](https://community.st.com/ysqtg83639/attachments/ysqtg83639/stm32-mcu-products-forum/80598/1/13902_STM32_ReferenceManual_11.pdf)。

Reset只准备，自动本启动零偏后READY；PA12完整按下释放一次触发，每启动至多一次尝试。
没有预置矢量、正反自动串接、串口启动/任意参数、Flash写入或闭环应用；当前Keil默认目标明确为新SINGLE_U模式。
真实MOE开启起保持400000us，接受释放起绝对截止420000us，启动提交2ms；先到期先停，不续期。
用户已决定50%与ARR1800，不重复请求相同授权；实际保护方案及现场操作条件仍须如实展示，运行另行安排。

## 载波与数据率分离：具体配置目标

全部外设配置从当前CubeMX6.12/FW_F1 1.8.6的.ioc生成，不手改生成区，不靠宏名称推断时序。

| 对象 | 新目标 | 目的/约束 |
|---|---|---|
| TIM1 | PSC0/ARR1800/中心对齐3/RCR39，TRGO UPDATE | 每半周期25us，(39+1)*25us=1000us一次UEV；20kHz载波，1kHz原始流 |
| TIM2 | 保持PSC71/ITR0 reset，CC1=175us开始SSI，PWM2 CC2=225us/TRGO触发双ADC | SSI名义21.33us在196.33us结束，至ADC225us约28.67us；不沿用旧200/250us |
| ADC | 双注入/原通道/12MHz/7.5cycle保持 | 名义采样+转换1.667us；保持硬件定时触发，IRQ延迟不等于采样相位 |
| TIM3/TIM4 | 保持1MHz | 独立期限和设备时间单位不变 |
| 输入/反馈 | raw1kHz，stride10反馈100Hz，3ms/30ms失联门限，10ms启动宽限保持 | 不盲目恢复参考约8k/10k原始处理；末尾50ms仍约50帧 |

中心重复计数器在overflow与underflow都递减，RCR39覆盖20完整载波周期。
必须固定启动相位：CEN0/MOE0、上数/CNT0、PSC/ARR/RCR完成预装，最终初始化UG加载重复计数状态，清状态，
再启用ADC及TIM2/TIM1。UG仅启动外设前允许，运行中仍禁UG/UDIS。HAL多次Init/最后UG及首次UEV必须按实际生成源码核对。
设计期望UEV在CNT0下溢，间隔1000us；不能仅凭RCR39文字认定硬件相位。

以bottom UEV为零，20kHz时225us对应第4周期顶部CNT1800：U低侧导通区为每周期12.5..37.5us，
ADC在其中心，距两边开关沿各12.5us；转换至226.667us仍在该区。175us同样位于顶部。
旧ADC250us落在bottom附近，U高侧导通，不能继续作为U低侧电流有效读数。
上述12.5us余量不是已测INA199建立/实际输出波形证明，模拟误差继续保留。

输出前需要在同一新固件的MOE0准备阶段核对自然事件/相位，不新增20kHz常驻ISR：
用已有TIM2/ADC事件及一致的TIM1 CNT/DIR、TIM2 CNT快照，重建UEV相位并核对预期bottom、周期/SSI完整性。
例如phase=(up?CNT:3600-CNT)，由phase_now-72*TIM2_elapsed_us模3600推回reset相位；快照读间偏差须有界并计入容差。
目标reset相位靠近0而非1800，允许实现核对的2us/144tick读取量化容差；不能用此容差覆盖半周期错误。
若不一致、跨方向读不一致或无法确定，则准备失败、不READY/不输出，禁止悄悄切换相位继续。
首帧启停和HAL UG不产生伪有效样本；真实底部相位/首帧时间必须由模型与最少板端准备记录核对。
这项寄存器检查不能替代外部PWM/模拟波形测量，但能拒绝采样在错误半周期的明显配置错误。

## 50%共同低窗：缩短最终开门事务

本模式启动后只保持同一组CCR，不需要带输出的多点更新。SINGLE_U不得调用旧board_update_scan_point，
旧最大60、ARR1799、CNT494、50us耗时等契约仅可留给显式历史模式，不能放宽成通用的高频扫描入口。

MOE0时装载CCR900/0/0并等自然UEV确认。完整载波相位x为0..3599tick，上数x=CNT，下数x=3600-CNT。
U/V/W共同低区是900<x<2700（12.5..37.5us），不再坚持“只准上数”的旧窗口。
候选一次CC4=1044上数事件（14.5us），允许最后开门准入x为1044..1980（14.5..27.5us）；
准入最迟点距下一高沿2700仍有720tick/10us。设置一个8us/576个72MHz周期的最终事务预算，留2us余量。
这里的8us是实现必须达到并证明的预算，不是已测WCET，也不能把原低频50us检查常量搬过来。

耗时输入验证/状态准备在MOE0阶段完成；最后准入处仍短事务复核撤销代次、状态、故障、输入年龄、绝对期限、BKIN/BIF和有效phase，
随后最短MOE写与再次读Break/相位/期限；异常必须先清MOE，日志/快照记录放在立即关闭之后。
不得挪走STOP/FAULT最终复核以满足时间预算，也不在窗口内做格式化/统计/等待。
Work须用ARM实际产物核对关键路径并让推进计数器模型覆盖576tick内外、迟到、DIR转换、短Break、STOP和NMI/异常关闭。
允许事件因IRQ延迟错过则拒绝本启动机会，不等下一圈自动重试。若最短生产路径仍无法满足，应报告实际阻塞，不扩大窗口冒充通过。
Cortex停止、无限异常或外部波形不由软件预算保证；TIM3也不是独立硬件断能。

## 电流诊断：候选1280count，需明确保护语义

名义静止星形模型：12V、R_eq=1.5*5.5=8.25Ω，L_eq=1.5*0.72mH=1.08mH，tau约130.91us。
T50us、ton25us，理想周期RL给U平均727.27mA、峰796.51mA、谷658.04mA；
在低侧区中点采样约723.97mA。两路相电流及推算W均须按当前已知符号/通道解释。
桥压降、反电势、接法、R/L/增益/Vref与母线实际误差未独立测量，数值不是安全上界。
400ms名义铜耗约1.75J，集中励磁远高于旧60tick；不能用原例程曾能转或额定1.5A推导本次不会过热。

旧256count约206mA采样门限低于新模型正常采样约724mA，不能保持原门限又宣称新动作可用，也不能删除诊断。
具体推荐为对齐专用绝对偏差1280count：名义1.03125A采样值；
选择依据是模型峰796.51mA乘1.25得到约996mA/1236count，再向上量化到1280，给出清楚的模型到诊断关系。
1.25只是此次实验筛选余量，不是已知硬件容差；电压偏高/电阻偏低时正常刺激也可能被拒绝，触发就停，不继续放宽。
固定本启动512帧零偏，U/V原始偏差和推算W均检查，整数缩放避免先截断均值，任一超限立即停；
ADC端点、零偏范围/噪声异常、窗口相位不合格也停。名义中点仍应留足ADC与放大器余量，实际过量程不可饶过。

这不是周期峰值限流；1kHz观察不能覆盖全部20kHz开关尖峰，也不替代驱动/供电保护。
普通12V适配器无外部可设限流，MS8313内部OCP不可用于实施1A级精确限流。
用户已经授权50%/ARR1800，但1280count保护变更及“当前无独立峰值限流”的实际限制应由Work连同操作计划明确呈现并取得决定，
不是再问一次是否同意50%。若用户不接受此保护口径，保留无输出构建，不制造一个保证安全的阈值。
不引入额外硬件或电流闭环作为默认隐藏前提；若用户要求真实峰值受限，则需另选实际可实现的限流方案。

## 单点取角、历史与操作收口

单U400ms最后50ms读取完整SSI：实际read_started>=350000us，read_completed<400000us，40..64帧、跨度<16count。
以真实开门为窗原点；接受释放起绝对420ms不延长，完整窗先记后结束。使用展开count的sum/count，不先截断机械角。
theta_e=wrap(d*p*(theta_m-theta_zero))，z=wrap(-d*p*theta_zero)，p7/d+1为有支持的候选，单U不辨识它们。
保留原始机械角、幅值/PWM/采样/config身份，自动P1A3或明确单点版本与解析器同批定义；不扩常驻遥测。
Reset只准备、PA12一次/boot、自动512零偏/READY、自动结果、STOP/BKIN/新鲜度/4000count包络/异常撤销保持。
50%固定矢量可能有机械响应，不能手持阻挡转子，也不能因无响应自动加时/重复。

旧七点z均值337.423095703125度与旧两点目标276.13037109375度、约61.29度差异及原七点19.5425>15度FAIL保留。
新PWM/相位/幅值结果不与旧配置混成一组校准；稳定仍只形成候选，不证明绝对磁链对齐，不写Flash/不自动应用/不进入闭环。
不要求无限硬件重复；先完整代码/数学/时序审查，必要的本轮最少板测为同固件MOE0准备确认和用户安排的一次单U动作。

## 首次20kHz板端启动失败与局部修复

用户31-14-10实测准备512帧/READY正常，按键后P1A3故障0x104（DEVICE|START_TIME），
接受释放后110us结束、start0、count0；未形成对齐窗口，不是400ms超时或电流超限。
最终时间预算和动作期限共用该故障位，110us远小于2ms启动期限，结合代码路径优先定位8us最终事务。
修复仅精简重复的设备时间/资格调用链：board一次取得新鲜时间传runtime，runtime仅核对当前状态、代次、
故障、原始/反馈有效性与年龄、启动/总期限；board仍在MOE前后检查驱动和相位。
8us门限、2ms/420ms期限、1280count诊断及所有停机条件保持；记录动作时标放在立即撤销检查之后。
主机用同样每次取时推进2us的夹具，旧实际board路径失败、新路径通过；推进3us超预算时新路径仍拒绝。
这些是软件开销压力模型，实际MCU开销/板端是否成功需新版本实测，不能把模型当WCET证明。
新串口与main注释版本31-14-21,SINGLE_U，不自动烧录或重试动作。
