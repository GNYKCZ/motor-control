# M2c：仅采样现场验收步骤（尚未执行）

这是待单独安排的现场任务，不是烧录/上电授权。用户能安排板卡、电机、下载/串口与供电，
没有示波器。本批只交付步骤和软件；每次实际操作前仍需明确安排板卡/供电/固件和现场操作人。
不能从串口日志推断PWM波形、死区、复位瞬态或功率桥高阻关断。

## 先分清供电、下载与串口

现有开箱资料已说明接口，不需要先补拍板卡正反面照片才能制定步骤。现场按实际丝印核对；
如与资料不同，只核实有差异的接口、版本或装配，再决定该次接法，不凭图片推定所有批次完全相同。

| 用途 | 资料中的接口与本次含义 |
|---|---|
| 功率部分供电 | 板左侧DC12V输入及12V开关；不能认为这一输入也代替了右侧5V供电 |
| 板上5V供电 | 右侧排母5V_IN/GND；12V与5V需分别供电，5V通常由下载器或串口模块提供；板子不提供5V输出 |
| 下载程序 | 右侧SWD接口；配套DAPLink可经Type-C连接电脑，向板提供5V并用于下载，具体引脚按该下载器接线说明 |
| 保存串口数据 | 本固件USART2输出，115200波特、8数据位、无校验、1停止位；板TX（PA2）接接收端RX，并共地 |

**Type-C插上能供电/下载，不等于一定有串口。** 先检查现有下载器是否带USB串口功能、
是否引出RX/TX/GND及电脑中对应端口；具备时可复用，不要求另买设备。若只有SWD下载，
才按实际接口确认可用的串口接收方式；不能把下载器的USB接口直接当作板PA2的数据通道。
串口“3.3V”指TX/RX信号逻辑电平，与板上需要的5V供电是两件事；不是要求再加一路3.3V电源。
不要把串口5V/RS232信号接到PA2/PA3，也不要把下载器上标注3.3V的供电/电压检测脚当作串口线。
本次只接收，不需要将适配器TX接板RX或发送控制命令。

## 现场前提与停止点

1. 对照现有开箱文字、板卡图片与实际丝印，核对板卡版本、U4装配、两路输入额定值及
   电源/下载器/串口针脚。丝印或装配有冲突时停止核实，不能把V2原理图当作实际装配证明。
2. **电机三根相线断开，是首次零电流候选采样的临时条件，不是电机正常工作的接法。**
   断电后将电机与功率桥之间的三相连接全部断开、分别绝缘，不短接相线；板上相线排母与
   其他电机连接器可能接同一组U/V/W，不能只拔其中一路却留下另一条连接。固定电机/编码器，
   保留本次使用的编码器连接（板载编码器按实际EN开关/丝印核对）。此时仍可读取角度。
   零偏候选要求静止且无相电流；三路IN低是低侧制动语义，不是桥高阻保证。
3. 12V路与5V路分别接至对应输入，**不要将两种电压并接**。5V_IN只选一个确认的5V来源，
   避免下载器、串口模块及其他5V输出互相并联或反向供电；连接板与信号接收端的GND。
   核对下载器检测脚/供电脚及USB接入是否立即送出5V；不清楚时先停下核实，不能靠试插判断。
4. 两路均断电、USB供电也已断开后接线。现场操作前，依据实际板卡额定值、电源/适配器能力，
   确定并记录两路设定、电流限制或保护方式及可观察的读数；没有限流显示/设置的来源如实注明。
   原写法中的固定12.0V/0.10A没有实测依据，**不是通用可照做值**；本文件不另给任意限流数。
   如保护能力或设定尚不能确定，该次上电条件未齐，不以不断增大限流的方式试出可运行值。
5. 停机路径须能直接切断12V和5V（包括USB经下载器/串口模块提供的5V），仅关12V不算完全断电。
   进入限流、供电异常、异常电流、发热/异味或板复位时立即关闭两路并停止，不自行提高限流续测。

开箱说明的“先12V、后5V或复位”针对原例程上电寻找d轴初始角度；原开箱程序还会转动后归位。
本仓库只采样基线不执行这些动作，不能照搬开箱的转动/对齐验收或用复位反复尝试。
该次供电顺序及下载器自动送电行为要在断电时确认，且只能在核对本次禁用输出固件后按明确安排执行。

## 固件与数据准备

记录被审固件完整40位commit、目标HEX SHA256、板卡/电机、下载器及是否复用其串口、
串口号、两路供电来源/设定/限流或保护方式与实际电压电流读数、接线记录和操作人。
没有读数的项目记为未测，不能填预期值冒充实测；已有板卡照片可用来记录接口依据。
先在电脑完成目标构建/主机回归，再核对实际待下载HEX哈希。
只有该次现场明确安排烧录/上电后，才用下载器将这一HEX写入；不用IDE自动运行/自动升级另一版本。

串口保存入口：先在电脑准备pyserial3.5。下面是待填参数的命令模板，**不要原样执行**；
实际串口打开仍属于该次现场安排。将变量填为实际值：`$serial_port`为确认的数据端口，
`$firmware_sha`为本次已构建/核对HEX的完整提交，`$board_record`、`$motor_record`为板卡版本与
电机型号/三相断开状态，`$supply_record`同时写明12V路与5V路的来源、设定、保护和实际读数。
例如字段格式可写“12V路：来源/设定/限流/观测；5V路：来源/设定/保护/观测；三相断开”，
但必须将每项换成真实记录；不把3.3V信号电平登记为第三路供电。

```powershell
python -m pip install pyserial==3.5
python tools/sensor_capture.py --port $serial_port --kind unverified_capture --seconds 10 --output build/captures/site_run_01 --firmware-sha $firmware_sha --board $board_record --motor $motor_record --supply $supply_record
```

脚本不发控制字符，但打开串口仍可能影响具体适配器的控制线；本工具已在打开前将DTR/RTS设低。
不清楚适配器连接时先核实。输出目录必须不存在，Ctrl+C停止接收但不能代替板卡断电。

无需板卡的合成示例（已明确不是实测；零SHA仅为合成元数据）：

```powershell
python tools/sensor_capture.py --input tests/m1/synthetic_m2c.txt --kind synthetic --output build/captures/synthetic_example --firmware-sha 0000000000000000000000000000000000000000 --board synthetic --motor synthetic --supply none
```

## 仅采样操作与验收

1. 确认两路供电均可随手切断、电机三相全部断开。按本次已明确安排的方式烧录/供电，观察并记录两路电压/电流，
   先保存10秒静止数据，不发任何使能/对齐/电流命令。
2. 期望M2C1、s=1、f=0、pwm=blocked、power=unverified；cn收齐512、cd=1、ca=0、cv始终0。
   观察u/v、min/max与候选均值是否远离0/4095撞轨，是否明显漂移；这只形成候选，不能将cv改为1。
3. cn完成后mv可为1，iu_mA/iv_mA应与raw和候选/名义系数自洽，但没有外部电流基准，不能验收真实A精度。
   静止候选的可用范围/噪声阈值要基于保存的原始分布再定，本批不凭任意阈值自动通过校准。
4. 如需要角度观察，仍保持相线物理断开，只在现场另行明确安排后手动缓慢转动编码器/轴，
   保存a和ma_mrad的单圈变化及16383→0；不做通电转动，不把此方向认定为电角度换相方向。
5. 任何f非0、s=2、ca=1、持续mv=0、raw撞轨、意外复位/运动、限流/异常电流、发热或接线变化，
   立即关闭两路供电并停止。保留完整raw.bin、records.jsonl、metadata.json，不删除失败段，不重启凑齐512。
6. 测试结束两路均断电（包括USB供电），再拆线。相线恢复接入属于后续另行安排的任务，不能在此次只采样中恢复后尝试转动。
   将原始记录连同固件/硬件/两路供电条件交现场负责人与设计复核；不要只发截屏或“看起来正常”。

日志保存包含未知/坏/半行；ok是采样包标志，UART行无额外CRC。仅据现有设备可报告串口字段、
故障状态和供电观察；输出真实波形、时序预算、校准精度、功率关断与实物闭环仍未验收。
