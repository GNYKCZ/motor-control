## 已遇到并修正的环境/构建问题

- 首次把厂家代码也按 Werror 编译时，HAL ADCEx 的多余括号警告导致停止。现保留厂家原字节及
  警告，自编代码仍 Werror；没有削弱运行期断言或改 expected。
- 主机 GCC 最初因子进程查找其运行库的 PATH 不完整而无输出失败。测试入口只为本子进程补齐
  编译器所在路径，不修改系统配置；之后才实际编译/运行 C 测试。
- 最小 MDK 元数据首次缺少其旧解析器需要的字段/架构 DLL/Windows 路径格式，构建失败。
  已补齐显式元数据并真实重建；未复制原作者的 `.uvprojx`。
- 缩减厂家源清单时确认 HAL DMA 虽在最终镜像被裁掉，链接解析阶段仍需其符号；去掉后
  链接明确失败，故保留该编译输入。未调用的 GPIOEx 源文件则成功排除。
- 自审期间检查到“前台先取时间，IRQ 后发布新包”的交错会形成巨大无符号差值，现用半周期
  次序规则区分倒序观察与超时；保留直接断言该交错的测试。
- 首包判断改用独立布尔状态，避免统计包数模回绕后把下一帧误当首次输入；
  序号/设备时间回绕已运行主机边界测试，没有声称执行过数十亿次实际板端采样。

## 尚不能宣称的结果与恢复方法

- **功率桥高阻关断能力未满足**：原理图 EN/nSLEEP/nRESET 固定高；PA8/9/10 低只代表停止调制，
  对 DRV8313 是低侧制动。必须确认实物 U4 型号、板卡修订及可用关断能力，再决定后续方案。
- NOT RUN：真实供电、下载、编码器/ADC采样、零偏/电流精度、相序/方向、nFAULT实际动作、
  SPI/ADC周期、IRQ负载/临界区最长时间、串口连通、上电瞬态与栈水位。本轮不操作硬件；
  后续按用户明确安排，在先写明供电/限流、指令范围、停机路径与停止条件后补证据。
- 32bit设备时间约71.6分钟回绕；算法按模差处理，最大合法间隔小于半周期。TIM4扩展要求 IRQ
  不被屏蔽超过65.536ms；当前仅静态路径有界，不能据此声称严格WCET或实测时间预算。
- 编码器 CRC 初值/多项式按手册实现；静止全零帧等物理断线情况不能靠CRC单独证明传感器连接。
  本批没有位置/电流闭环，后续需真实帧、磁场状态和故障实验验证。
- 序号表示软件完整发布次数，不是硬件TRGO累计计数；较短的中断丢拍不保证可定量还原。
  失联阈值可检测长时间没有事件，不能把它称为完整高速无丢样记录器。
- 栈静态调用图包含库函数指针/弱异常处理循环等 Unknown；静态数值不能当最坏栈峰值证明。
