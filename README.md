# Motor Control

基于 STM32 的电机控制与 FOC 学习工程，用于逐步实现、验证和记录电机驱动、编码器读取及电流、速度、位置控制。

## 工程范围

工程、源码、测试及学习笔记都放在本仓库目录内。当前已加入 [STM32F103 M1 采样基线](firmware/stm32f103/README.md)：
只采集原始值与导出状态，永久禁止 PWM 调制；功率桥高阻关断能力仍是未满足项。
软件构建/测试与板端验证分别记录；M2c固件已烧录并取得有限板端采样观察，尚无可运行的关节仿真模型。

M2a 新增 [纯 FOC 数学模块与来源/验收契约](docs/m2a_foc_contract.md)：只在主机测试中验证
电流坐标变换、联合电压限幅及SVPWM占空比，不接入M1固件，也不使能PWM或闭环。

M2b 新增 [双轴电流PI软件契约](docs/m2b_current_control_contract.md)：直接复用M2a，
验证最终联合电压限幅反馈、显式积分状态及失败不提交；当前只在主机运行，尚未接入板端电流闭环。

M2c 增加 [零偏候选与名义测量](docs/m2c_sensor_contract.md)：完整帧整数统计、
前台名义电流/机械角、版本化串口记录和[单独的仅采样现场步骤](docs/m2c_sampling_check.md)。
512帧只形成候选，校准通过标志恒false；仍永久禁止PWM。2026-10-27已取得用户提供的一条
双电源正常状态及USB-only故障片段，供电/接线和证据限制见[板端记录](docs/m3b_feedback_integration.md#已有板端证据与本批限制)。

同级的 `../资料/` 是本地参考资料目录，不属于本仓库，不上传 GitHub。需要借鉴套件源码时，按具体学习任务引入必要文件，保留原作者说明，并核对相关许可。

M3a 新增[连续机械角与两种速度估算](docs/m3a_feedback_contract.md)：显式状态、真实时间差和固定窗口，
主机合成轨迹用于验证量化/噪声与延迟；实机性能尚未验证。

M3b 增加[板端反馈路径的软件集成](docs/m3b_feedback_integration.md)：原始流逐帧检查、
每10帧有界交接、前台计算连续角和两种速度，M3B1分别导出有效状态。
用户自烧录M3B1后报告`f=8,fo=1`，板端反馈检查未通过，确切二进制未经独立核验。
后续[M3B2分步导出与计时诊断](docs/m3b_timing_check.md)已取得用户故障摘录：
多个日志步骤超过约1ms输入间隔，仍出现积压。当前[M3B3精简诊断帧](docs/m3b3_compact_log.md)
仅发16字段，删除不发送的展示换算，每poll只做一个有界整数转换。用户已自行烧录并提供正常短摘录；
这支持基础功能观察，尚不能证明持续运行质量。
真实时序/速度性能仍未验收；这不是速度闭环，PWM仍永久禁止。

## 开发与验证

P0 已按用户接受的基础功能口径完成，证据范围为下载校验和有限日志摘录；
P1 从[受控输出入口与门控设计](docs/p1a_output_gate_design.md)开始，先核实可到达的命令路径，
再确定限值并接入输出。当前固件仍为 M3B3 只采样，尚未实现 P1 输出。
首批[P1a1无输出命令往返](docs/p1a1_command_link.md)增加STATUS/STOP与固定帧CRC，
ARM/PULSE明确拒绝；用户已有一次COM9的STATUS严格匹配回执，开口破帧仍未确诊，不代表串口全工况稳定。

后续[P1a-2 一次性PWM门控设计](docs/p1a2_pwm_gate_design.md)细化三相提交、故障与期限；
默认无可输出profile，会话防重放策略与首次非零输出条件仍待确定。本项是设计，不是板端输出验收。

[P1a-2 A 软件准备](docs/p1a2a_pwm_preparation.md)实现三相门控、BKIN和独立期限及主机交错测试；
生产profile仍为空，ARM/PULSE拒绝，未执行板端输出。

1. 每个独立工程放在本仓库内的独立子目录，并提供自己的构建和接线说明。
2. 修改后先完成适用的编译或软件验证，再进行硬件测试。
3. 硬件测试记录应注明板卡、电机、供电、固件版本及观察结果。编译通过不等于硬件运行已验证。
4. 使用 Issue 记录问题，使用分支和 Pull Request 管理后续修改。

软件安装包、工具安装目录、编译中间文件及本机凭据不纳入版本控制。
